## §2 每批要走的那条链路（**逐条都吃过亏，别省步骤**）

`会诊 → 纪要（含分歧 + 父侧裁定）→ 需求档 + 设计档 → 设计评审 → eng_coder 实施 → 分歧审计 → 交付代码评审 → 提交`

| # | 纪律 | 来源（吃过什么亏） |
|---|---|---|
| 1 | **设计档必备九节 + 涉及流程/数据流必配图** | 用户 2026-09-12 裁定，所有批次适用 |
| 2 | **锚的谓词必须写全三件事**：何时点（历史 vs 工作树）· 何谓改（新增/修改/删除分开）· **自指**（锚所在文件自身是否在集合内） | 三次栽在同一坑：批 2「零新增用例」被审计揭穿 → 批 4 T-G9 → 批 6 T-AP9（**登记 D-37**） |
| 3 | **判定族字面只追加、绝不替换** | 批 6 设计评审轮次 1 的 🔴：设计档自相矛盾（「追加」vs「替换 + 逐处改断言」），而零改面纪律禁止改断言 |
| 4 | **禁止用 PowerShell 做代码文件的读-改-写**（`Get-Content -Raw` 按 ANSI 读 UTF-8、`WriteAllText` 写 UTF-16 ⇒ 乱码 + 丢换行）。脚本级改写一律 **node 显式 `utf8`**，写后核 `U+FFFD` = 0 | 批 3（父侧本人）与批 6（实现者）**两次同因事故** |
| 5 | **交差验证是常态**：设计评审 → 实施 → **独立分歧审计**（explore 子代理）→ 交付代码评审（advisor code）→ 修复轮。**审计抓到的真缺陷已经有 4 个**（批 4 的 codex 中断计振、批 4/5 的工具层与 CJK「假锁」、批 6 的「手搓等价物 + 无消费者」🔴） | — |
| 6 | **设计评审的发起权**：默认在用户（我呈递就绪并提醒，不自己开）；**用户显式授权时可代签**（2026-09-13 夜即此模式，已记入 METHODOLOGY.md） | ENGINEERING-MODE 规则 |
| 7 | **每两次设计评审之间插一次代码评审** | 否则同一会话里的第二份设计文档会拿到**收敛轮**提示词（只验证、不找新问题）+ 别人的 prior ⇒ 令牌声称覆盖的文档从未被真正评审（**D-35**，已修） |
| 8 | **`eng_coder` 必须传 `designToken`**（参数传，不写进任务文本）；大任务传 `stages`；预计 >9 分钟用 `background: true` | 平台 600s 墙钟 |

## §3 环境事实（不知道这些会浪费一整轮）

| # | 事实 |
|---|---|
| 1 | 插件工作副本 = **实时插件**（web profile 里是 junction 指向 `D:\DSH-Portable\plugins\dsh-thincoder-suite`）；**改 `lib/**` 或提示词需重启 DSH 才加载**（模块在启动时读入）。改 `docs/**` 立即生效（我在读盘）。 |
| 2 | `designToken` 是**会话内存态**（`session-state.json` 刻意不持久化它）。**DSH 重启后写门禁会拒绝主代理的写**，报「engineering mode is ON and no design token」；**恢复路径 = 过一次 `eng_coder`**（它有磁盘回填）。**登记 D-36**。 |
| 3 | **DSH 大约每 2 小时重活后因资源耗尽崩一次**（2026-09-13 三次：01:49 / 11:27 / 18:41，均为原生失败 + 「虚拟内存/系统资源不足」）。**建议在批次之间的空档重启 DSH**，并关掉底噪大户（ChatGPT 桌面 ~1.3 GB、微信 ~0.4 GB）。机器总内存 15.76 GB。 |
| 4 | 会诊/评审都跑在 `ctx.jobs` 后台 job 里（**进程内**）。崩溃会**连带杀掉在飞 job**，job 注册表随之销毁（`job_output` 查不到）。所以**每完成一步就落盘**是本仓的生存法则。 |
| 5 | 设置页的「生效值」来自 **user 层 > base**；`cordis.patch.yml` 只是 bundle 缺省。 |
| 6 | 测试：`node --test`（零依赖、零网络、零真实 LLM）。当前基线 **360/360**。 |
