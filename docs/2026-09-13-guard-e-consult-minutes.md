## §2 分歧与父侧裁定

### 2-1 结算侧比对基准：闭包捕获 vs 读活 state ⟶ **采纳闭包捕获**

| 方案 | 主张 |
|---|---|
| 读活 `state.pendingDocPaths`（v4-pro 首次表述、kimi） | 派发后至 settle 前无第二写点，等价 |
| **闭包捕获 `castDocPaths/castDocHash`**（glm、astra） | 不作等价性推理，直接消灭依赖 |

**父侧裁定 = 捕获**（`advisor.mjs:1957-1961` 铸造块后立即捕获，finalize 只读捕获值）。判据：① 二者在当前代码下**确实等价**（单飞入口检查 `:1819` 早于铸造 `:1946`，窗口内无第二铸造），但捕获让正确性**不依赖**该不变式——将来若有人在窗口内加一个 `pendingDocPaths` 写点，读活版本会静默退化成「自比恒真」（守卫失效且无测试会红）；② 捕获形态可直接落**机器验锚**：finalize 签发块内 `state.pendingDoc*` 出现次数 = 0（AST/grep 级可断言），把「不许读活 state」写成编译期事实而非注释纪律。风险不对称：捕获的代价是两行局部变量，读活的风险是守卫静默失效。

### 2-2 子代理写入：全场扫描 vs 会话键自然 miss ⟶ **采纳全场扫描（拦）**

| 方案 | 主张 | 支持 |
|---|---|---|
| **拦**（按执行者会话键查槽位会 miss，故须**扫全表**） | 「窗口内任何人无合法写权」（主/子/他会话同构）；子代理是典型漂移向量 | v4-pro、glm、astra（**3/4**） |
| 不拦（按 `sid:mechanism` 查，子会话 id 不同 → 天然 miss） | 子代理改在审文档属边角情形、归兜底；全表扫描引入跨会话误拒 | kimi |

**父侧裁定 = 拦，且**扫全表**（`inFlightJobs` 是模块级 Map，遍历所有槽位取 `reviewType==="design" && docSet.length>0` 者）。判据：① 哨兵（预闸）存在**全部意义**是「在被烧掉之前拦住」——被拦的写若落到 settle，结局同样是 settle 侧拒绝 + 白烧一轮评审；漏掉一个已知向量等于把哨兵的价值打折；② 与写门禁 `:158-160` 的 depth 豁免**刻意相反**，理由是两闸护的东西不同（写门禁护「令牌轴」，depth>0 是 sanctioned 实现者；预闸护「窗口完整性」，**该文件正在被评审这一事实与写入者身份无关**）；③ kimi 的「全表扫描引入跨会话误拒」**属实**，登记为 🟡 O-E1（见 §3），但它的爆炸半径 = 一个有界窗口内、对同一份文档的一次工具调用（逃生门齐备且廉价），低于漏拦的代价。

### 2-3 失配是否计一次三振 ⟶ **不计（且不扩七 kind 词表）**

| 方案 | 主张 | 支持 |
|---|---|---|
| **不计**：漂移分支对 `recordDesignSettlement` **零调用**（既不加 1 也不复位），早返回绕过通用计振尾 | 漂移 = **行为造成**（带外写入），非评审管线故障；批 4 已有同族先例（`interrupted`：`kind !== "interrupted"` 豁免用户主动中断）；三次竞态即可锁死**完好**文档集且唯一出口是新会话（而新会话治不了漂移）；会撒谎的诊断面（护栏会指引「换路由/模型」） | glm（首次表述反对）、astra、kimi（**3/4**） |
| 计振，新 kind `doc_drift`（guidance 第 8 行，七 kind 契约改八 kind） | D-G1 把 design 侧从 `MAX_ADVISOR_ROUNDS` 豁免，其成立前提是「三振护栏是 design 侧唯一的界」；漂移不计振 ⇒ 漂移-重发循环**零账目进度、无上界** | v4-pro（1/4） |

**父侧裁定 = 不计**。判据（按权重排序）：

1. **护栏计的是「插件自身健康度」，不是用户行为**。七 kind 里 `timeout/context_limit/empty/turn_cap/stale/token_persist_failed/review_failed` **无一例外都是管线自己的故障**——它们的指引全是「改我方的配置/参数/路由」。漂移是评审管线**工作正常**（PASS + 回显命中）而外部改了文件；把外部失误计成管线失败，会污染 `settlementGuardText` 的「最近三次 kind」诊断面，指向错误的修法。**与本仓最痛的一课同族**（批 6 全批就在修「把不同死因坍缩成同一句话」）。
2. **误锁不可逆 vs 循环可自愈**。本仓已两度实测「误红/误锁」的代价（D-37 两次：必然红的断言淹没真实回归；D-34：一次 miss 销毁已获授权）。护栏的唯一出口是新会话，而漂移**不是文档集的病**——新会话不解决它。反向的「无上界」担忧：真实上界是**每轮烧一次真实评审 LLM**（自限），且预闸已把最可见的漂移源（`write/edit`）变成事前响亮拒绝 + 真逃生门。
3. **`stale` 不复用**：已回代码核实（`advisor.mjs:2266-2272`）——`stale` 的机械定义是「job **完成**但 **finalize 被跳过**（代际失配，走 `:2265` 早返回）」。漂移发生在 finalize **内部**、`completed` 为真、`advisorRound` 照常 +1。复用 `stale` 会破坏 D-G5「机械事实归类」的词汇表纪律（同一标签指两种不同事件）。
4. **配套**：`SETTLEMENT_KIND_GUIDANCE` **保持七行不扩**，并在其上方加注释钉死理由（防将来「顺手修一致」把漂移塞进计数面）。

> **未决风险如实登记**：若将来出现「带外写入者每窗必漂 → 无限免费重评」，其解法是**独立漂移计数器**（与三振正交、各有其出口），属新批次，**不在批 6b**。本裁定的可翻转性已写进设计档 §12。

### 2-4 fail 朝向：扁平 fail-closed vs 分层 ⟶ **采纳分层**

| 方案 | 主张 | 支持 |
|---|---|---|
| **分层**：窗口**已确认**在飞 → 判定故障 **deny**（fail-closed）；**无法确立窗口存在**（注册表读取本身故障）→ 放行 + warn | 朝向由不变式决定：fail-closed 的正确形态是「**无法证明目标在冻结集之外**时按在其中处理」，而「窗口存不存在」是另一个问题——窗口未确认时无可护之物 | glm、v4-pro（**2/4**） |
| 扁平 fail-closed | 任何异常一律 deny | astra、kimi（2/4） |
| 扁平 fail-open | 监听器异常一律 `next()` + 诊断日志 | astra 首次表述（1/4） |

**父侧裁定 = 分层**。判据：① 它把 fail 方向**绑在不变式上**而非「安全侧」的直觉上——「已证有窗口」是前置条件，故障方向只对前置条件成立之后的部分求朝向；② 实现上可结构化保证：**窗口判定区（`inFlightJobs` 遍历 + 槽位字段读，纯模块态、不可抛）先于且独立于 `try` 区**，`try` 只包目标解析/归一/成员判定 ⇒ `catch → deny` 在结构上只可能发生在窗口内；③ 与相邻写门禁的 fail 方向**确实相反**（写门禁 `eng.mjs:180-182` `catch → next()` 无条件放行），满足已定前提。

### §3.1 O-E5 订正（批 13 / R-33 —— 「登记说错了」第三次同物种；**本批不修，只订正**）

> **订正三要素**（设计档 §9 边界 1 / D13-5 · D13-6 · D13-7；需求档 US-5 / AC-8）。**「不修」≠「判非缺陷」**——本项是**带触发条件的已登记后续项**。

**① 已证事实**（本次回盘实测，三家会诊收敛）

- **固定基下的形态无关性成立**：`normalizeDocPath`（`lib/doc-hash.mjs`）= `resolve(p).replace(/\\/g,"/")` ⇒ **相对路径 / 绝对反斜杠 / 绝对正斜杠**三形态在**同一基**下归一为**同一串**。故原登记说的「评审传相对而写传绝对 ⇒ miss」在**基相同**时**不成立**。
- **两侧同函数同基**（禁令遵守中）：评审侧 `computeDocHash` → `pendingDocPaths` → 冻结集；闸侧 `lib/eng.mjs` 的预闸 —— **单一 `normalizeDocPath`，无第二份实现**。

**② 残余风险（真实失效链，比登记的「miss」更坏）**

- **基分叉**（`process.cwd()` vs 会话 cwd；`lib/advisor.mjs` 自己就在用 `session.header.cwd`）时：
  - **hash 侧 fail-closed**：读不到 ⇒ `ok:false` ⇒ 不绑文档集 ⇒ 续期恒拒（**可用性**损伤，方向安全）；
  - **冻结侧 fail-open**：冻结集锚在**错根** ⇒ 闸侧对真实绝对路径写**静默放行** ⇒ **在飞窗口的文档冻结失效 = 保护性损伤**。
- **前提勘误**：「机制内部自洽 ⇒ 无缺陷」**是错的**——`自洽 ≠ 保护`：一致地锚在**同一个可能错的根**上是自洽的，**不证明那个根是对的**。
- **未验证项**：分叉**是否在真实部署发生**未观测（需活会话；本机不可重启）——这是「本批不修」站得住的理由**之一**，不是「无风险」的证明。

**③ 修法方向（预授权，免得将来重新会诊）**

- **入口边界按会话 cwd 预解析**：`resolve(sessionCwd, p)` 在进入 `computeDocHash` / 闸判定**之前**把相对路径**钉成绝对路径**；`normalizeDocPath` **仍是唯一归一点**。
- **明文划界**：本方向**不属于**本档 **§1 结论 4** 那条禁令的射程——**禁令禁的是「自造 cwd 版 / 第二份实现」**（会劈开单点实现），而本方向只改**入口基**、不新增归一点、不复制 `normalizeDocPath`。
- **前置条件（结构性）**：**闸侧当前拿不到会话身份**——`makeDocFreezeGate` 以**全局** `tools/pre-execute` 钩子注册，闭包只吃 `getFreezeSet` ⇒ 修法需先有 **DSH `pre-execute` 载荷的会话身份核验**（登记为跨批次约束 R-35）。
- **触发条件**：首次在**活会话**观测到 cwd 分叉。**另立批次**（守卫 E 机制变更）。
