## §四 决策与理由

| # | 决策 | 理由 | 被否决的备选 |
|---|---|---|---|
| **D-1** | ④ 采纳「**先 trim + 去重，再判上限**」 | 与 JSDoc 一致，且**对用户更宽松**（重复项不再吃配额）；上限仍是 `MAX_DOC_PATHS` | 改 JSDoc 迁就实现 —— 那等于把「去重」这个合理语义删掉 |
| **D-2** | ⑦ 改成**包装器**而不是再加一个断言 | 现形「先跑完再核对」在**并发/多写点**下没有证明力；包装器把「期间未变」变成结构保证 | 保持现状只改注释 —— 解决不了语义问题 |
| **D-3** | ⑧ 用「能解析才断言 + 不能解析记 diagnostic」 | 真实档会变，腿不该因**无关文档**的增删而红；但**静默跳过**等于假腿 ⇒ 必须留痕 | 固化成 fixture 副本 —— 会与真实档脱节（且要维护第二份） |
| **D-4** | ⑨ 只收窄谓词，不动解析结构 | 最小面；解析器的形状被其它腿锁着 | 顺手重写解析器 —— 超出除尘范围 |

## §五 方案（FR-x）

- **FR-1**（④）`isValidDocPathList`：`const uniq = [...new Set(v.map(p => p.trim()))]` ⇒ `uniq.length > MAX_DOC_PATHS` 拒；全为非空字符串才通过。
- **FR-2**（⑥）`task_update` 描述与 schema 各加一句只读字段声明。
- **FR-3**（⑦）`withZeroWrite(ws, fn)`：取 sha → `fn()` → 断言 sha 不变 → 返回结果；**21 个调用点**逐点改成「包装 + 独立断言拒绝码」（拒绝码断言保留原语义，只是不再依赖「已经算好的 result」）。
- **FR-4**（⑧）T-7③ 改条件断言 + diagnostic 留痕。
- **FR-5**（⑨）`commandArgsOf` 谓词改 `m[1] === name`。
- **FR-6**（⑩）注入点加成本注释。

## §六 机制伪代码

```text
withZeroWrite(ws, fn):
  前置：ws 是会话工作区；fn 是**会尝试写**的同步函数
  后置：返回 fn() 的返回值；若期间文件字节变了 ⇒ 抛断言错误（腿红）
  before = tasksFileSha256(ws)
  r = fn()
  assert.equal(tasksFileSha256(ws), before, "拒绝路径必须零写入")
  return r

isValidDocPathList(v):
  前置：v 任意
  后置：纯函数，不抛
  if !Array.isArray(v): return false
  uniq = unique(v.map(p => String(p).trim()).filter(t => t !== ""))
  if uniq.length > MAX_DOC_PATHS: return false
  return v.every(p => typeof p === "string" && p.trim() !== "")
```

| 腿/闸门 | 判据 |
|---|---|
| **T-4a**（并入既有 T-4 块） | ④：`docPaths` 传 **9 个但含重复** ⇒ 去重后 ≤8 ⇒ **通过**（旧实现会拒） |
