# 设计（批 28）：对外收口 —— 上游报告包 ⊕ 版本哨兵 ⊕ 结项说明

- 日期：2026-09-26
- 状态：**已交付（批 28）**——设计评审 3 轮至 PASS · 实现 = eng_coder `eng-dsh-6`（在自检阶段被兜底 abort，产物经只读审计确认完整）· 宿主验收 `node --test` **567/567** · 交付审计与全部订正见 §7
- 来源：**平台侧三问题**（本机实测，非本仓可修）+ 批 26 的「被撞」教训（0.1.7 换契约是我们撞出来的）
- 前序：[`dsh017-batch26-design.md`](./dsh017-batch26-design.md) · [`dsh017-full-alignment-design.md`](./dsh017-full-alignment-design.md)

## §1 背景与用户故事

**三个平台侧问题（都有一手证据，但都不属本仓）**：
① `job_output` 读全文**对所有作业都崩**（含平台自产）；**干净移除 profile 自带 rc.1 副本后仍崩** ⇒ 平台自身读法缺陷（批 26 §8 的环境实验）。
② **沙箱下子进程执行会挂住**：dsh 子代理跑 `check` 命令**既不报错也不返回**（实测挂 8 分钟、日志 0 字节；宿主同命令 7.24 秒全绿）——正确行为应是**报错**（fail-closed），挂起只能靠兜底。
③ **advisor 三形态并存**：coord 超时 / main 截断 / bce 内联成功——内联路径存在但**条件不明**（批 26 的 `pathForm` 已让它**可查**，但没人系统看过）。

- **US-1**：把这三件事整理成**自包含的上游报告包**（现象 · 最小复现 · 证据 · 影响 · 建议），别人（或未来的我）拿到就能复现，不用再翻会话导出。
- **US-2**：**版本哨兵**——插件装配时读平台版本并与「已知契约面基线」对照，不匹配就**响亮警告**并指向契约矩阵 ⇒ 把「换契约被撞」变成「换契约被提示」。
- **US-3**：**契约面巡检**一条命令出一个报告（九条锁 + 平台版本 + 落盘目录状态），运维/交接时一眼看清。
- **US-4**：**结项说明**——把 24→28 的批次脉络、九条触点矩阵、护栏机制（令牌/docHash、锚、锁、宿主验收）写成常设页，供将来任何会话接手。

## §2 方案

### §2.1 上游报告包（US-1）
新增 `docs/upstream-2026-09-26-platform-issues.md`（常设档）：三条问题各含「现象 / 最小复现（含命令）/ 一手证据（文件:行 或作业 id 与字节数）/ 影响面 / 给上游的建议」；
附 `scripts/repro-platform-issues.ps1`：**只读**复现（起一个 2 秒后台作业试 `job_output`·汇总 `pathForm` 分布）。**沙箱挂死那条腿的执行方式（评审 #5）**：宿主直接跑 `.ps1` **进不了 dsh 子代理沙箱**，且真挂住会陪挂（实测 8 分钟）⇒ 该腿**经插件派发一个作业**去跑（或明确标注为「人工/受助」步骤），并给它**独立超时**（复用 `HOST_CHECK_TIMEOUT_MS` 量级）；超时即记「**疑似挂住**」并继续，**绝不陪挂**，输出一段可直接贴进 issue 的报告。

### §2.2 版本哨兵（US-2）
插件装配期取平台版本，**按钉死顺序取第一个可得的**：① `ctx.pkg?.version`（宿主注入）② profile manifest 的 `dsh` 依赖声明 ③ 进程可见的 `@deepseek-ai/dsh-core` 包版本；**三者皆不可得 ⇒ 标 `unknown` 并走 A28-3 的告警分支（不猜、不崩）**。**告警与巡检返回里必须附「版本取自哪个源」的 evidence 字段**（`source: "ctx.pkg" | "profile-manifest" | "package-json" | "unknown"`）——本机 profile 层实测就是 rc.1/rc.2 混杂，源②会稳定假阳性；有 evidence 才能把「真换契约」与「环境 skew」分开（评审 #6）；读取逻辑集中在一个 `readPlatformVersion(ctx)`（单一事实源，供哨兵与巡检工具共用）；与 `lib/contract-baseline.mjs`（新增，记录「本轮验证过的平台版本 + 九条触点期望形态」）对照：
- **一致** ⇒ 静默；**不一致** ⇒ `console.warn` 响亮告警（含「未知版本」分支）+ 在设置页/工具描述里给一句指向 `docs/dsh017-*.md` 的提示。
**纪律**：哨兵**只警告不阻断**（拒启动会变成新的砖化源）。

### §2.3 契约面巡检（US-3）

**helper 落点（评审 #1）**：`readPlatformVersion(ctx)` 与**九条谓词**同住 `lib/contract-baseline.mjs`（D28-2 的单一事实源）；`test/platform-surface.test.mjs` 与巡检工具**都 import 它**，不各自留字面。**求值方式口径（第 2 轮评审订正）**：九条锁**一律按「源码文本 / 夹具文本」求值**——已交付的 `test/platform-surface.test.mjs` 九条**全部**经 `src(...)` 读源码文本断言（`test/platform-surface.test.mjs:30/86/187/234` 等），**零真实网络、零真实 LLM、零子进程**；工具侧沿用同一取法（与 D28-4「只读」一致，也不复现本批 §1 的挂死面）。**取不到文本 ⇒ 记 `"unknown"` 而非 `false`**（与 A28-3「不猜」同源）。返回形状**统一为一处**：`locks: [{ id, ok: true|false|"unknown", evidence }]`（`evidence` 记「读自哪个文件/片段」）——初版稿在 §2.3 与 §2.4 写了两种键集，此处订正为唯一形状。
新增工具 `contractWatch`（只读）：一次调用返回 `{ platformVersion, locks: [{ id, ok, evidence }…] , jobsDir: { files, bytes, oldestDays } }`；
九条锁的判定**复用** `test/platform-surface.test.mjs` 的谓词（抽成共享 helper，测试与工具同一事实源，避免第二份字面）。

### §2.4 结项说明（US-4）
新增 `docs/dsh017-program-closeout.md`：批次脉络（24/25/26/27/28）· 九条触点矩阵**只做「指针 + 摘要」**（权威源 = `lib/contract-baseline.mjs`；批次历史细节链回各批设计档，避免三处并存漂移——评审 #7） · 四道护栏（令牌 docHash · 锚/AC · 常驻锁 · 宿主验收回执）· 以后遇到平台换契约的**标准动作**（先跑巡检 → 对照矩阵 → 开新批）。

## §4 决策
