## 一、总目标

让**长任务里的目标与未收口承诺，不再依赖“记得”**：把“该做什么、做到什么算完、还欠什么”从**静态纪律**（只提醒、会衰减）升级为**每回合可见 + 收尾可拦 + 开工可查**的三层机制；并用一份**交付核对清单**把“有没有漏”变成机械可查。

**判据一句话**：在一个跨多回合的长任务里，① 目标与验收判据每步都出现在模型上下文；② 模型宣告结束时若有**本会话**未收口承诺，回合被推回一次并要求处理（有上限、用尽即诚实放行）；③ 新会话/恢复会话开工时，**本会话**的未收口事项被**主动摆到面前**；④ 交付前逐条核对清单，缺项必须在报告里明写。

## 二、用户故事（功能层）

- **US-1 目标锚定**：作为使用者，我给一个长任务立目标时，必须同时给出**可机器验证的验收判据**（跑什么命令 / 看什么输出 / 查什么文件）；给不出判据的目标**被拒**，并提示“没有可验证判据的目标是愿望不是目标”。**形态补充（2026-10-14 设计档回填，解评审轮 1 🔴1）**：判据在**建目标之前**写成（`goal_criteria set` 不填 `goal_id` 即为**待绑**），建目标成功后自动绑定——故「先写判据、后立目标」是机械可实施的顺序，不是鸡生蛋。
- **US-2 每回合可见**：只要目标处于 active，我在**每一个回合**都能在模型上下文里看到「目标 + 验收判据 + 审计句」。**范围收窄（2026-10-14 设计档回填，解评审轮 1 🟡5）**：①「已用/剩余回合 + 接近预算上限的警告」**本批不做**（宿主轮次读数可得性未验证，不造读数）⇒ 登记为设计档 §14 **L-2**；② 审计句是**一条**（"只有判据的检查实际跑过并通过才算完成——弱证据、计划、摘要都不算完成"），不是两条；③ 注入行整串 ≤ 512 字符。
- **US-3 收尾推回**：模型宣告结束（本回合零工具调用）而存在未收口承诺时，**该回合被推回**并收到一条明确的提醒（点名缺什么、怎么补）；推回次数**有上限**，用尽后放行并留下诚实声明，不得静默通过也不得无限循环。**范围收窄（2026-10-14 设计档回填，解评审轮 3 🟡4）**：推回的**前置含「存在活跃目标」** ⇒ **无活跃目标的会话不会触发推回**（此时只有 FR-3 的注入行提醒在场）。理由：三族谓词都与"目标/落章"同域，短任务里每次普通编辑都被催会变成纯骚扰；要防忘评审的长任务本来就会立目标。
- **US-4 开工接管**：新会话或恢复会话开工时，若**本会话**存在未收口事项（有未验证改动 / 有未评审改动 / 活跃目标缺判据），这些事项被**主动注入**到本次开工的上下文（摘要 + 一行指路）。**范围收窄（2026-10-14 设计档回填）**：团队黑板（`team.md`）上的未收口条目**不在本批射程**——那需要跨插件读取，登记为设计档 §14 **L-1** 遗留。
- **US-5 三个对象分家**：目标 / 台账 / 审计是**三个不同生命期的对象**——目标短（会话内、每回合注入、带判据）、台账长（跨会话、按需查、写入门机械校验）、审计只追加（谁在何时声称了什么）。**本批射程（2026-10-14 设计档回填）**：本批交付「目标」（FR-1…FR-4）与「台账写门」（FR-7）；`tasks.md` 的三职**拆分**与审计对象的独立化**不在本批**（登记为设计档 §14 L-1 / L-4）。
- **US-6 开关与豁免**：开关面 = **插件配置文件（六键，全 base-only）+ 工具面 `anti_drift_config`**（get/set，键名与取值类型闭集校验，工程模式禁写）。**默认值分档（2026-10-14 设计档回填 + 用户裁定，解评审轮 2 🔴1）**——按「打扰度」而非按「机制」分档，**四个默认**逐条留裁定痕：
  - **注入行 `antiDrift.inject` = 默认开（ON）**：低打扰（每步至多一条尾部快照，同文不重发）、且**是本设计的可见性本体**——默认关等于把「忘目标」这个病根留在原地。
  - **完成门 `antiDrift.completeGate` = 默认开（ON）**：封闭门、只在「宣告完成」那一刻生效（不在建目标/日常工具上设卡）；它挡的是**假完成**（最坏的一类损失），误伤面由「指路文案 + 一次工具调用即可解」兜底。
  - **回合推回 `antiDrift.pushback` = 默认关（OFF）**：唯一会**改变回合命运**（不让模型结束）的机制；照抄上游克制选择（其两个 guard 亦默认 OFF 且工程模式禁用）。
  - **台账写门 `antiDrift.ledgerTransitionGate` = 默认关（OFF）**，先单队试点。
  - **逃生门**：四键都能由 `anti_drift_config` / 配置文件即时翻转（写后本会话下一次读取生效——先例 = 本插件既有 `configDefaultEngineering` 的读法）；**其余两键**（`verifyHeuristic` / `caps`）随其所属机制默认（`verifyHeuristic` 默认 `true`、`caps` 默认 `{pending:1, verify:2, advisor:3, total:6}`，且 `caps` 子键有闭集与范围校验）。
  - **收窄（2026-10-14 设计档回填，解评审轮 1 🔴4）**：**设置页不做**——本仓对用户层（`settings.yaml` 白名单）键的既有纪律是三面同步（`config-store.mjs` ⊕ PUT 校验 ⊕ 设置页表单，`METHODOLOGY.md` D-29 行），那是一条独立交付面；本批六键全 base-only ⇒ 工具面已满足实际需要且**零新增用户层写入面**，设置页登记为设计档 §14 **L-7** 遗留。
  - 工程模式（`eng` 开着）沿用其既有纪律，不与本机制叠加出双重推回；任一机制的失败**不得**让本回合报错或让插件装配失败。
- **US-7 平台能力如实**：若某版本平台缺 `agent/turn-stopping`，则该面按设计档 FR-8 关闭并**恰一行** warn；**降级路径 = FR-3 的注入行仍然在场**（它是独立面，不随推回面关闭），故"提醒"仍在、"拦截"没有——诊断面（`contractWatch` / 启动哨兵）**如实标注降级**，不假装等价（解评审轮 1 🟡8）。
- **US-8 交付核对清单**：一批工作交付前，我按一份**固定清单**逐条打勾；缺任一条 ⇒ 交付报告里必须明写「清单未满，缺 X」，**不得静默交付**。（清单本体 = 设计档 **§11 末段**的「父侧交付前核对清单 8 条」——解评审轮 2 🔵11：原先误指 §13。）

## 三、非功能标准

- **N-1 预算自持**：平台无内置回合预算（`agent-loop/README.md:220`）⇒ **本插件必须自持推回预算**，且预算用尽后**必然落回放行**（fail-open 到「正常结束」），绝不允许出现“无上限推回”。
- **N-2 监听器不抛**：`agent/turn-stopping` 的监听器**抛错会把该回合变成 `{kind:'error'}`**（`contract-regressions.spec.ts:346-363`）⇒ 监听器体必须整体 try/catch，任何内部失败都降级为“不推回”。
- **N-3 前缀缓存友好**：每回合注入的文本必须在**内容未变时逐字节相同**（同内容不重复注入 / 复用同一字符串），否则会把“记不住”换成“账单爆炸”。
- **N-4 零改面（含一处显式豁免）**：不改 advisor / eng / escalate / consult 四条既有链的**语义**与既有测试期望；不改 `team-link` 黑板既有行格式、上限、seq 分配与写权限口径。**豁免（解评审轮 1 🟡9）**：本批的 **C10** 把 F12 恢复链的监听名从 `agent/session-start`（**两个平台版本都不存在**）换血为 `agent/created`（并保留旧名作跨版本垫片）——这**确实改变真机行为**（工程模式与 advisor 轮次首次真正跨重启恢复）。这是**修复半条断链**而非语义变更：写入侧一直在写盘，读取侧从未触发；既有用例路径因垫片保留而全部仍有效（实测三处命中，见设计档 §13 C10 落地记录），并新增 `T1b-C10` 正向回归锁。
- **N-5 可测**：每条新机制必须有**可在套件内跑**的夹具腿（stub agent / stub 黑板 / 假 `turn-stopping` 派发），不得只靠真机；负控腿（关掉机制的腿必须红）与正腿成对。**跨仓档位（解评审轮 1 🟡10）**：本仓腿落 `test/anti-drift.test.mjs`（**A-1…A-6 · A-8…A-15** + 五条负控）；**A-7（team-link 台账写门）落 team-link 仓的 `host-half.test.mjs`**（该仓既有单档测试载体）。
- **N-6 平台面契约锁**：**四个**宿主面进 `lib/contract-baseline.mjs` 的触点矩阵，`contractWatch` 可读——`agent/turn-stopping` · `systemPrompt.context` · `agent/created` · `tools/post-execute`；签名漂移 ⇒ 响亮告警且**不阻断**（沿既有哨兵口径）。
- **N-7 文档卫生**：新档登记进 `docs/README.md` 地图；`README.md` / `CHANGELOG.md` / `contractWatch` 描述与实现**同批同步**；涉及重启才生效的面必须写明。
- **N-8 零新依赖**：不新增运行时依赖；消息对象按平台字面形自建（`{id, role, source, content}`，先例 = `team-link/lib/index.js:11623-11630` 的有意偏差），不为此扩导入白名单。

## 四、边界与登记面

### §4.1 本批不做（逐条给理由）

1. **不做 RAG / 长期记忆检索**：那是另一条链（thincoder 的 `MEMORY.md` 是索引与召回），与本批“长任务不跑偏”正交；混进来会让本批无法收敛。
2. **不复活 checklist 工具**：thincoder 明确**删除了** checklist（工具 + 文件 + 启动注入），理由是“两套待办跟踪是重复，删一留一”，且裁定**“注入面纯移除，不承接”**；本批的注入对象是**目标与未收口事项**，不是另一份待办清单。
3. **不做文档双面机检 / 批次档机检**：thincoder 自己在 v2 撤除了 V1–V4 机检（标注“无对应机检器”）；本批只做**可数的字符串/结构判**。
4. **不做无限推回**：见 N-1。
5. **不接管平台原生 goal 的续轮语义**：平台 `goal-round-driver` 是**回合级重入**（新 `turn/start`），与本批的回合内推回是两件事；本批不修改其行为，只在其之上补“判据”与“可见性”。
6. **不迁移 thincoder 的 SQLite 台账**：本机黑板是 markdown 追加式；本批只补**写入门**（`done` 需 `claim` 来历），**不动存储形态**、**不做派生读数的跨插件消费**（后者 = 设计档 §14 L-1）。

### §4.2 登记面（已知风险与遗留，逐条登记）

- **R-34-1**：`agent/turn-stopping` 是**平台扩展点**，非本插件可保证的契约；上游若改派发条件（如增加“已有 next-step 则不再触发”的新分支），推回会静默失效 ⇒ 靠 N-6 的契约锁 + 真机冒烟腿兜底。
- **R-34-2**：推回把“模型宣告结束”变成“继续干活”，**对用户是可感知的行为改变**；用户可能觉得被打断 ⇒ 默认关闭 + 单回合上限 + 明确的可关闭开关。
- **R-34-3**：`agent/created` 的 `source` 取值 `startup|resume|clear|compact`（`runtime-types.ts:125`）——`compact` 也会触发，若在 `compact` 上做“开工接管”会把接管清单重复注入 ⇒ 设计须限定 `source` 集合。
- **R-34-4**：黑板是**跨会话共享文件**，无锁；两条机制同时读写可能读到半行 ⇒ 读面必须容忍解析失败（fail-open 到“不注入”），不得抛。
- **R-34-5（本批新增登记）**：本仓**既存红基线**——全量 `node --test` 实测 **595 / 591 绿 / 4 红**，其中 `T-AP7` 的 1 红（`lib/advisor.mjs` 的 `.abort(` 预算超限）来自**工作树既有未提交改动**、与本批文件不相交；另 3 红由本批引入并已修复（2 = `DOC-HYGIENE` 表形，1 = `T-AP9` 授权面）。详见设计档 §14 **L-8**。
