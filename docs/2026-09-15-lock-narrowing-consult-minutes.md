## §2 四问裁定

### 裁定 1：归一化的定义

**管道（写死在 `test/guard-e.test.mjs`，作为既有 `stripComments` 的包装；`stripComments` 本体逐字节不动）**：

```js
// normalizeExec = stripComments（原样复用，实现零改）→ 逐行 rtrim → 丢空行 → join("\n")
const normalizeExec = (src) => stripComments(src)
  .split("\n").map((l) => l.replace(/\s+$/, "")).filter((l) => l !== "").join("\n")
```

**语义（精确表述，必须写进设计档）**：锁的是「**可执行行的字节与顺序**」；**注释层（文字 / 位置 / 行数 / 缩进）完全自由**。

**明确不做的两级归一化**：
- **不归一 token 间空白** —— 空白在 JS 里**承重**（`a+ +b` ≠ `a++b`，`return\nx` 有 ASI 语义）⇒ 朴素空白归一 = **制造逃逸面**（假绿）。
- **不归一 EOL** —— 逐字节锁**今天**就 EOL 敏感，A 既不增也不减；加 EOL 归一 = 第二个归一规则 + 域外扩权。

**逃逸面逐项裁定**：

| 形态 | A 下 | 机理 |
|---|---|---|
| 注释文字/位置/行数/缩进改动 | **绿** ✅ | 设计目标 |
| 代码与注释**位置互换** | **红** ✅ | 代码行顺序变 |
| 把代码**挪进注释** | **红** ✅ | 该可执行行从归一形态消失 |
| 注释**解封为代码** | **红** ✅ | 新增可执行行 |
| 代码行内 token/空白改动 | **红** ✅ | 无空白归一化 |
| 改**缩进** | **红**（登记为预期严格面） | 缩进保留在锁面内 |
| 字符串/正则内含 `//` | **红（方向安全）** | 剥离导致 mangling ⇒ 与夹具失配；**域前提由裁定 4 的断言钉死** |

### 裁定 2：夹具形态 = **存预剥离归一态**

`WRITE_GATE_FIXTURE` 从「79 行原始带注释副本」改为「**47 行归一态**」的静态字面，**字符数以机械推导为准，禁止手抄**。
**必备自检**：`assert.equal(normalizeExec(WRITE_GATE_FIXTURE), WRITE_GATE_FIXTURE)` —— 重归一恒等 ⇒ **抓「夹具里混进注释 / 尾空格 / 空行」**。

> **v4-pro 的机理不成立，但结论采纳**：它主张「两侧同剥会让字符串内 `//` 被两侧同样吞掉 ⇒ 假绿」，父侧实测该逻辑不成立；但**预剥离形态本身**仍是对的（它让比对只有**一侧**做剥离 ⇒ 语义更单一，且那条幂等自检才有意义）。

### 裁定 3：顺序锁 = **加，一条，声明式**

```js
const WG_END = "\n\n/**\n * 守卫 E 预闸"   // 提为具名常量，与 :903 同字面
assert.ok(stripComments(engSrc).indexOf(WG_END) === -1,
  "A2 顺序锁：右界标记本身是注释 ⇒ 必须【先切片、后剥离】；全档剥离后该标记必失（防将来把剥离提到切片之前）")
```

**四家全部要求加**（codex / glm / v4-pro / kimi），形态一致。
**不过锁的判据**：它钉的是**测试自身的切片机制**，而标记文本早已被 `:904`+夹具事实钉死 ⇒ **零新增钉死面**。
**它堵的退化路径真实且近**：T-E18 的 `:943` 已在算 `stripComments(engSrc)`，未来一次「先剥再切」的重构是最自然的坏改法——没有本条时只会看到 `:904` 一句费解的「边界不可定位」，然后**改标记绕过，锚就这么死了**。
**只加右界一条**（起点 `export function makeWriteGate(` 是**代码**，剥离后仍可定位，判别力全在右界）。

### 裁定 4：`frozen` 断言 —— 移到归一化体 + **修拼写缺口**（用户裁定）

**(a) 移到归一化体上是「补课」而非放松**：本档**已有明文惯例**——负向代码属性断言一律跑在剥离产物上（`:889`「负向断言只看**代码**（注释不是调用）」· `:942`「注释里引述前缀字面不算实现」）。`:907` 是全档**唯一**跑在原始文本上的负向断言，只是字节锁时代的遗物；其消息「守卫 E 未被并进写门禁（D-E1）」本身是**代码语义**。⇒ 保护力**零损失**（守卫 E 若真被并入，证据必是代码级）。

**(b) 修拼写缺口（父侧实测为真缺口）**：`"frozen".includes("designFreezeSet")` = **false**（freeze 无 n）⇒ 今天的断言**只拦 `frozen: ` 文案，从没拦过「把预闸函数拖进写门禁」这类合并**——而那正是 D-E1 要防的最重一类。改为：

```js
assert.ok(!/(designFreezeSet|makeDocFreezeGate|"frozen: )/.test(norm),
  "A2: 守卫 E 未被并进写门禁（D-E1；注释不参与；合并签名三选一出现即红）")
```

一行、零新增锁面、**修的是一个今天就存在的真缺口**。

### 裁定 5：注释脱节副产物 —— **接受，不补支点注释句**（用户裁定）

舍弃 kimi 的「钉 3 句支点注释」提案。**理由**：
1. **那就是本批要消灭的「锁注释」本身**——批 10 三次重基线里**两次的税**就是它。
2. **切片内每条承重不变式都有可执行行承载**（depth 门 · **sole-carrier 的 `if (!state.designToken) {`** · 内层 fail-closed · 三态路由三元式 · 外层 fail-open catch · deny 两串）⇒ **没有「只有注释承载」的判据**。
3. **残余风险登记**为**新边界**：「注释层自由（内容 / 位置 / 存废），漂移不再有锚捕获，权威 = 设计档 + 评审」；边界-12 关闭。

### 裁定 6：域前提自检（**加**）

```js
assert.ok(!slice.includes("/*"), "A2 域自检：剥离器在切片上必须逐行局部（块注释跨行吞并 = 前提失效）")
```

**父侧实测切片内 `/*` = 0 次** ⇒ 立锁零成本；它是**裁定 1 全部推理的支点**（保证剥离是逐行局部的），并顺手灭绝 `fro/*x*/zen` 这类拼接绕过。
