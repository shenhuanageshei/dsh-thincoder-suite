## 问题 1：`mode: exempt` 会不会变成新白名单

**结论：在已定六条形态下它结构性成不了白名单——⑤ 已把它豁免的东西抽空了。** exempt 豁免的只是「声明义务」（不写 `doc-shape` 就躲过 ④ 的红）；而 ⑤ 把腿 1/腿 3/事实腿改为全档常开 ⇒ **事实校验不再骑在声明上**。exempt 档里的 `（N 项 id=X：…）` 照样被数、被分组、被比对；别的档的 `require-facts: id@N` 照样把 exempt 档内的出现算进次数（出现计数是全域的）——**exempt 连一处已注册事实的出现都藏不住**。它唯一逃掉的锚表/AC 表/compare 是配置型义务，而「未来的非批次档」本就没有这些表。边际收益 ≈ 零。

但剩余三个可滥用面，各有一条便宜的「滥用必被发现」：

1. **用 exempt 缩配置** → **单键约束**：`mode: exempt` 是声明里唯一的键，与任何其他键共存 ⇒ 红。
2. **谎称「无可数事实」逃腿 4**（唯一有真实收益的形态：有 AC 形表/锚形表的档谎称 exempt）→ **内容一致性检查（机验）**：exempt 档内出现任何 `（N 量词：`/`id=` 标记、或裁定保留的第二层（面级结构触发）命中 ⇒ 红。于是「本档无可数事实」从自白变成**被机器验证的声明**：不写标记的档有没有 exempt 都一样（N-1 天花板与豁免无关），写了标记的必被抓。**若设计砍掉面级结构触发，exempt 就成了腿 4 的唯一逃逸口——这条必须保留并扩展到 exempt 档。**
3. **橡皮章豁免** → **理由必填**（值内联理由，沿用 orphan 锚的 `（豁免：…）` 先例）；理由不可机验，但豁免住档头 + README 登记行（R-25 既有）⇒ 设计评审必读。

# Q1：`mode: exempt` 会不会变成新的白名单

**裁定：按 ④ 现在的形态（光秃秃一个 `mode: exempt`），会。** 它有白名单的全部本质属性：作者自写、无枚举、无人盘点、永不复审。它唯一比 D16-2 否决的那种白名单好的地方是「显式、可 grep」——但**可 grep 不等于会被 grep**。

**先破除一个幻想：「不可能滥用」达不到。** 如果把 exempt 通道整个删掉（所有日期 ≥ CUTOFF 的档必须全键声明），作者会改用**文件名不带日期前缀**来躲 ④ —— 逃逸从「档内一行显式声明」变成「文件名一个不可见的缺席」，**可见性反而更差**。所以设计目标只能是「**滥用必被发现**」，问题只剩发现通道是什么。仓里已有三个同族先例可拼：

| 机制 | 出处 | 杀什么 |
|---|---|---|
| **R1 双向登记锁**：豁免集作为常量枚举在谓词档里（`EXEMPT_DOCS = ["2026-09-20-foo.md"]`），档内 `mode: exempt` 无登记项 ⇒ 红；登记项无对应档 ⇒ 红 | `AP_TEST_AUTHORIZED` 授权仪式 + 腿 4 反向腿（锚 ↔ AC 双向锁）同构 | **未授权的豁免**（作者单方面写 exempt 逃不掉——必须同时动谓词档，而谓词档是全仓锁面最重的面：锁面变更须显式声明 + T-LC2 等值锁盯着）。**「由评审而非作者决定」由此落地**：豁免决定以测试档 diff 的形态出现在每一次评审面上，不再是档内私事 |
| **R2 理由强制 + 键互斥**：`mode: exempt` 必须配非空 `exempt-reason:`（空 ⇒ 畸形红，与「键值为空必红」同律）；且 `mode: exempt` 与 `anchors/acs/compare/require-facts/count-marks` 任何配置键同现 ⇒ 畸形红 | `（豁免：…）` 必须带理由的既有先例（A10 行） | 「豁免变默认懒人选项」的激励错配——写 exempt 的成本被拉到 ≈ 写最小声明 + 动登记锁的成本 |

| **R5 收口盘点**：收口 checklist 加一步「grep `mode: exempt`，逐条确认仍成立」；登记锁使这一步恒为一次 grep | 批 16 的「产物比证词可靠」（R-56） | 流程层的最后兜底 |

**必须写进设计档的张力（不藏）**：R1 与 **D16-3（声明住档内、测试不做第二份真相源）正面相撞**——登记锁就是一份测试侧的名单。我的辩护：D16-3 防的是「名单与档内现实漂移」，而 R1 是**双向锁**（两个方向都红），漂移本身被机制灭绝；且 `AP_TEST_AUTHORIZED` 已是同形态先例（测试档枚举 + 仪式）。**但设计档必须明说这是对 D16-3 的一次有界例外**，理由 = 豁免集小、安全相关、集中化收益大于漂移风险（而漂移已被双向锁封死）。备选落点 = `docs/README.md` 索引（R-25 已管顶层档登记，豁免作为索引行的一个标记）——省一份新解析面、但锁的仪式弱于测试档；我倾向前者，这是给父侧的决策点。

# Q3：跨档「值」的归一化——规则与各自的失败形态

**先点破一个结构性事实**：两种出现形态把「值」已经预归一化了——全枚举形的值 = (N, `·` 项集)，裸引用形的值 = N。「8 条 vs 新增 8 条 vs 8」里的「新增」**住在标记外的散文里，从不进入抽取**。所以归一化问题比看上去小：它不是「怎么从散文里认出同一个数」（那是 62% 误报的老路，N-1 禁行），而是「**在标记载荷上做什么、不做什么**」。每条规则附带它放过的真漂移：

| # | 归一化规则 | 放行的合法差异 | **放过的真漂移（失败形态）** |
|---|---|---|---|
| **R1** | 抽取点 = 标记载荷本身；**标记外散文永不入值** | 「新增 8 条」与「8 条」与「8」（措辞全在散文里） | **散文语义反向**：一处写「新增（8 条 id=X）」、另一处写「删除（8 条 id=X）」⇒ 数值同 ⇒ 绿。**机制只证数值同一，不证语义同一**（与需求档 §5.1 #4 一致，写进 §9） |
| **R2** | 标量等值 = 整数值相等（`Number(N)`） | `08` 与 `8` | **全角数字 `（８ 条：…）` 与中文数字 `（八条：…）` 整标记不可见**（不匹配 `[0-9]+`）⇒ 全角排版档整条腿静默失效；千分位 `（1,024 条：` 同样不可见。修它们 = 扩大命中面 = 与 Q2 的保守方向对冲 ⇒ **不修，登记** |
| **R3** | **量词不入等值**（id 即同一性，量词是呈现） | 「8 条」与「8 项」与「8 档」跨档同 id | **量词漂移不可见**（条↔项↔档）；更险的是 **id 撞名且数值碰巧相等 ⇒ 静默绿**——id 碰撞的两个方向都是 fail-open，只能靠批次前缀纪律（`b17-…`），上一轮已登记，此处复述 |
| **R4** | **事实分三型，类型由 `require-facts` 声明**：标量（只比 N）· 标记集（比项集）· 键值对集 | 标量型事实在多处用全枚举/裸引用任意混合 | **标量型的代价：同 N 不同成员 ⇒ 绿**（两处各列 8 项、换了 2 项，数值同 ⇒ 静默绿）。**这是显式选择的 fail-open，设计档必须把它写成类型的代价，不许藏** |
| **R5** | 集合元素的归一**只做 trim + 内部空白折叠**；键值对集同理（cell 文本） | 「腿 1」与「腿1」、换行差异 | **注释/饰词差异 ⇒ 红**（`腿1（锚 A7）` vs `腿1`）——**这是故意的 fail-safe 方向**（误报可见、改文案即解）；而 P-2 的教训正是「cell 里的订正语必须暴露」⇒ **任何更深的文本归一（剥括注、同义词、全半角折叠）都会把真污染洗成绿——禁止，写成原则** |
| **R6** | 混合形态比较：全枚举形贡献的是 **N 本身**（腿 1 已证 N == 段数）⇒ 混合比较退化为 N==N；项集只在**两侧都是全枚举形且事实为集合型**时才比 | 一处全枚举、多处裸引用（「重复压到最小」的既定形态） | 集合型事实只有一侧有枚举时，**成员内容无对侧可比 ⇒ 只受了数值保护**——登记 |
| **R7** | CHANGELOG 侧值 = **登记行声明的绑定规则**抽出的字面（`本批 Y` / `基线 X` / `**N/N**` 的 N），整数比较 | 「新增 8 条」（散文）与 `本批 8`（计数行）与 `（8 条 id=X）` | **CHANGELOG 条目散文里的计数不受绑**（散文写「新增 8 条」而计数行写 `本批 9` ⇒ 跨档腿只看计数行 ⇒ 散文漂移不可见）；**绑定规则写错对象 ⇒ 运行时才红**（方向 fail-safe，可见） |
| **R8** | **值域 = 非负整数**；semver / SHA 类事实**不进标记语法** | — | 想给版本号建事实 ⇒ 语法外 ⇒ 静默无事发生。那是「锚定现实」方向（上一轮已登记为后续批次），**不许为它撑破标记语法** |

**元原则（建议作为设计档 §9 的一条定理性陈述）**：**每一次归一化都是一次 fail-open 决策**——归一只许修呈现（整数、trim、空白折叠），永不许修语义（同义词、饰词、量词、散文）。这张表本身就是验收锚：评审逐行核「哪类真漂移被哪条规则放过」是否都被设计档 §9 逐字登记。
