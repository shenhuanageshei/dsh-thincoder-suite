## 一、总目标

让**你与模型看着同一套账本**：你列的任务、模型的进度、卡在谁身上、什么在等你拍板 —— 在看板、对话、每回合注入行、工具四处**永远一致**，因为它们读写的**是同一份 `tasks.json`**。

**判据一句话**：① 你在看板上看到的任务集合与状态，与模型在**同一回合**读到的**逐条相同**；② 完成一件任务必须留下**一句凭据**（跑了什么、看到什么），否则完成不了；③ 卡住的项**必须显式在场**（区分"等外部"与"等自己动手"）；④ **待你决策的项单独成区且置顶**；⑤ 依赖缺席（无 better-sidebar / 无团队台账）时**降级但不崩**，机制本体不受影响。

**非目标**（本批明确不做，逐条给理由）：

1. **不做第二份存储** —— 看板**零存储**，只是渲染面。理由见 §四 D-2（用户原话：两套账本 ⇒ 会骗人的看板）。
2. **不做"看板上打勾/改进度"** —— 用户明确否决。理由：完成必须带凭据，点一下就勾掉会把这套机制的根废掉。
3. **不做截止日期字段** —— 用户明确否决（"暂时不用"）。
4. **不做团队台账源** —— 排第二批。理由：`dsh-team-link` 自己正在「批 R」中（截至 2026-10-16 仍有未提交改动），依赖它的实时形状不稳。
5. **不做 SQLite** —— 用 JSON + 原子写。理由见 §四 D-5（本批是单人单写、无并发冲突，而原版上 SQLite 的动因正是"并发写冲突太多"）。
6. **不做模糊文档解析** —— 结构化文档源**只认有明确列结构的表格**；靠猜列名解析自由文本必然产生假读数。
7. **不新开注入通道** —— 任务摘要**并入既有**的每回合注入行，不新增第二条 `systemPrompt.context` 贡献。理由：宿主去重是"同文不重发"，多开一条 = 多牺牲一份前缀缓存收益。
8. **不做任务的删除与归档**（评审 #15 补录）—— 台账**只增不删**：`完成` 可重开，但 `evidence` **不清空**。理由两条：① 删除会让「凭据留痕」失去意义（US-2 的凭据一旦能随条目被删掉，就等于没有）；② 归档是**生命周期管理**（体量/世代/回收），属独立问题，排第二批。
9. **不用 `tools/pre-execute` 拦原生 `todo_write`**（评审 #1 补录，**撤销纪要 D-83-3**）—— 理由见 **§13.6 D-15**（前提已消失 + 硬拦会误伤宿主自身的回合级规划）；替代措施 = 软引导 + 静态断言腿。

## 二、用户故事（功能层）

| # | 用户故事 | 验收判据 |
|---|---|---|
| **US-1** | 作为使用者，我新增一件任务时能顺手写清「**怎么算做完**」，并可标优先级与「为什么做这件事」 | 建任务时 `check` 非空校验；`priority` 与 `why` 为可选字段 |
| **US-2** | 作为使用者，我把任务标成**完成**时必须写一句「跑了什么、看到什么」；**没有凭据就完成不了** | 无凭据的 `done` ⇒ **拒且零写入**，文案指路 |
| **US-3** | 作为使用者，我能看到任务在**五态**间流转：`待办 → 已接手 → 在做 → 完成 / 卡住`；标"卡住"时必须带**原因** | 非法迁移被拒；`blocked` 缺 reason ⇒ 拒 |

## 三、非功能标准

| # | 标准 | 判据 |
|---|---|---|
| **N-1** | **单一真相源** | 盘上只有一份 `tasks.json`；看板侧零持久化（grep 证明看板客户端无写盘调用） |
| **N-2** | **原子写** | 复用既有 `writeFileAtomic`；崩溃点为替换前后，不留半文件 |

| **N-7** | **秘密禁令** | 看板与复制话术**不呈现任何凭据值**；`tasks.json` 中出现疑似凭据形态 ⇒ 拒写并提示 |
| **N-8** | **可机检** | **11 条用户故事逐条至少一条机器腿**（见设计档 §九 **T-1…T-15**，其中 T-4 拆 a/b ⇒ 共 **16 条腿**）；US-5（同源性）按 **§13.4 的两句口径**断言（看板 ≡ 工具读 = 集合相等；注入行 ⊆ 看板）——**不是**抽样、也**不是**三方全等 |

## 六、机制伪代码（关键函数签名 + 前后置条件）

```
// 写门（唯一写入口）
applyTaskTransition(file, { id, to, evidence?, reason?, blockedBy? }) -> Result
  前置：file 是合法的 tasks.json（否则创建空结构）
  前置：id 存在于 file
  后置：to === "done"  ∧ evidence 去空白为空        ⇒ 拒（"完成必须留凭据"），零写入
  后置：to === "blocked" ∧ reason 去空白为空        ⇒ 拒，零写入
  后置：to ∉ ALLOWED_MIGRATIONS[from]              ⇒ 拒，零写入
  后置：任何拒绝路径 ⇒ 文件字节不变

// 同源渲染（看板与注入行走同一个读函数）
readTasksView(scope) -> { decisions: Task[], active: Task[], done: Task[], counts }
  前置：scope 含工作区标识
  后置：畸形文件 ⇒ 返回空结构 + 一行痕（fail-open），不抛

// 注入摘要（并入既有行，不新开通道）
renderTaskDigest(view) -> string
  前置：无
  后置：纯确定性（同 view ⇒ 逐字节同输出）；不含时间戳/百分比/步数
  后置：空集合 ⇒ 空串（该段不出现）

// 结构化文档只读源
parseChecklistDoc(text) -> { rows: CheckRow[] } | null
  前置：文本须含表格
  后置：列结构不达 ≥4 列或无可识别状态列 ⇒ 返回 null（**不猜、不部分解析**）
  后置：识别状态枚举 {TODO, DOING, BLOCKED, PASS, FAIL} 与"验收五件"是否齐备
```

## 七、状态与 schema（谁写谁读）

`tasks.json`（绑工作区，同址于既有 `.thincoder/`），`version: 1`：

| 字段 | 类型 | 谁写 | 谁读 |
|---|---|---|---|
| `id` | string（`t-<n>`） | FR-2 | 全部读面 |
| `kind` | `"work" \| "decision"` | FR-2 | FR-4/5（分区） |
| `title` | string（非空） | FR-2 | 看板 + 注入行 |
| `status` | 五态枚举 | FR-2（经 FR-1 写门） | 看板 + 注入行 |
| `check` | string（**怎么算完成**） | FR-2 | 看板 + 完成门 |
| `evidence` | string（**跑了什么、看到什么**） | **仅**完成时 | 看板 |
| `blockedReason` / `blockedBy` | string / `"external"\|"self"` | 仅 `blocked` 时 | 看板（**卡住分区置顶**） |
| `priority` · `why` | number · string（可选） | FR-2 | 看板 |
| `createdAt` / `doneAt` | ISO string | FR-2 | 看板 |

**看板侧：零持久化**（N-1）；**注入行侧：只读**（不写盘）。

#### §13.6.1 D-15（新增决策 · **撤销 D-83-3**）

**不加** `tools/pre-execute` 门去拒绝原生 `todo_write`；改为**记录显式撤销**并改用软引导。理由两条：

1. **前提已消失** —— D-83-3 的目的是「拦旁路、保写路径唯一」；而用户随后拍板 **D-13（丙：零复用宿主任务面、不推镜像）** ⇒ 我们已经**不关心**宿主那个面，不存在「写路径分叉」要保。
2. **硬拦会误伤宿主自身功能** —— 原生 `todo_write` 是宿主的**回合级规划**工具（`todos` 投影每回合清空即证）；拦它等于**禁止模型做本回合规划**，与批 34「不靠削减能力来防漂移」的立场相悖。
   **替代措施**：设计档 §2.2 加一句**软引导**（任务台账走 `task_*`；`todo_write` 只当本回合草稿）+ 一条**静态断言腿**（本仓零 `todo_write` 调用点）。
   **代价如实说**：模型仍可能在 `todo_write` 里写任务而你在看板上看不到 —— **软引导只降概率、不阻断**；接受这个残余风险，因为它比「砍掉宿主规划能力」代价小。

#### §13.6.2 D-16（新增决策 · **决策项的完成凭据语义**）

`kind: decision` 条目的 `evidence` **不是**「跑了什么命令」，而是**「结论是什么 + 谁拍的」**（例：`「等批R落地后再提 FR-7 —— 用户 2026-10-17 拍板」`）。同一条写门（T-1）照样咬：**空凭据 ⇒ 拒**。

理由：决策项「完成」= **有人拍了板**，不是「某条命令跑通了」；若不区分，决策项的 `evidence` 会退化成一句空话（或干脆留空 ⇒ 被门拒掉）。
