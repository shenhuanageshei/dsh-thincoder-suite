## §3 ★ 已知陷阱（**本会话实测，逐条都付过代价**）

| # | 陷阱 | 表现 | 防法 |
|---|---|---|---|
| **1** | **行锚手术吞整行** | 用「替换行首子串」改一条超长行 ⇒ **旧行尾留在新行里**（格数变多）或**整行被吞** | **改长行用整行替换**；**改完必数**：表按 `\|` 切格、历史行数一条一条数、小节标题数 |
| **2** | **格内字面竖线** | 在 markdown 表格格内写 `\|`（含「说明文字里提到它」）⇒ 该行多一列 ⇒ 闸 A 红；**任何渲染器里都会切列** | **格内不写那个字符，连说明也不写**；用「竖线」二字 |
| **3** | **计数与列表不同改** | 标题写「五条」而表有 6 行 · 一处写「AC 15」而表有 16 行 | **计数必须「列 id 出来数」，不能只报一个数**；**改列表与改计数同一次编辑** |
| **4** | **时点值被当现况读** | 「598 行」「AC 14」是某轮时点的真值，被当日读数用 | **任何数带 as-of**；**不声明会立刻过期的量**（如本档行数） |
| **5** | **PowerShell 吃引号/反引号/UTF-8** | `node -e` 里的单引号与反引号被吃 · 提交消息里的引号被吃 | **一律写临时 `.mjs` 文件跑**；**提交消息一律 `git commit -F <file>`** |
| **6** | **`eng_coder` 1800s 兜底会硬中断** | 报告全丢，**工作树留下看起来完整的实现** | **大任务用 `background: true`**；**中断后改「从盘上逐点测量」，不依赖报告** |
| **7** | **DSH 重启清空 job store** | 完成通知到达时 `job_output` 报 unknown job | **同上：产物是唯一可靠的记录** |
| **8** | **`advisor` 会失败（transport 层）** | `DeepSeek API request failed` · `finish=error` · `blocks=0` | **不自动重试**（硬规则）；**报告给用户，等指令** |
| **9** | **设计评审结算护栏** | 同一文档集连续 3 次「无可结算」⇒ **零 LLM 拒绝，会话内不可解，只能新开会话** | **每轮都要有实质改动**；**3 轮内必须收敛**；**轮次 3+ 严格只核上表** |
| **10** | **`docs/README.md` 未登记 ⇒ R-25 红** | 新建档后 `node --test` 红在 T2 | **建档即登记**（与建文档同一次提交） |
| **11** | **工程模式的写门** | 无 design token 时**非 `.md` 写入被拒**（`denied: engineering mode is ON and no design token`） | **需要改非 `.md` 时走 `eng_coder`**；**父侧只改 `.md`** |
| **12** | **EOL 逐档不同** | `docs/**` 与 `CHANGELOG.md` 是 **CRLF**；`test/**`、`lib/**` 是 **LF** | **改前测、改后测**；用 node 显式 `utf8` |
