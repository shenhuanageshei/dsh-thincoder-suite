## §1 总目标（一句话）

**让「原子写失败」这件事**——① **不再必然发生**（`rename` 遇 Windows 短暂占用时有界重试），**并且** ② **一旦真的失败，调用方与用户能知道**（不再只有一句 `console.warn` 被吞掉）。

---

## §2 背景与问题

### §2.1 靶子

`lib/dsh-home.mjs:65` 的 `writeFileAtomic`：`mkdirSync` → 同目录 tmp `writeFileSync` → `renameSync`，**失败即抛、无重试**（仅 best-effort 清 tmp）。三个 store 共 **5 处**调用（摸底档 §4 已订正计划里的「4 个 store」），另有一处**同类但独立**的 `renameSync`（`lib/config-store.mjs:226` 的原子删除路径）。

### §2.2 两条已登记的缺陷，实测判为**同源**

| 登记 | 原文 | 实测结论 |
|---|---|---|
| **`R-51`** | 批 14：「`test/session-state.test.mjs` 的 `AC-17` 偶发（`saveTokenRecord` 返 `false`），诊断指向 `writeFileAtomic` 的 tmp+rename **在 Windows 上可被 AV/索引器短暂持有而 EPERM**」 | **机制面成立**：仓外探针实测「目标被另一进程持有句柄 ⇒ `renameSync` 抛 **`EPERM` / errno `-4048`**」 |
| **`R-13`** | 批 9 台账：「`test/session-state.test.mjs` **T6（TTL 清扫）的既有时序 flake**」 | **★ 「时序」是误诊**：失败原文 `actual ['keep','malformed','stale1','stale2']` **恰是那次写落地前**的文件内容；该断言与时间无关（`stale` 与 `keep` 的 `lastSeen` 余量充足），唯一路径是「**那次写没落地**」 |

⇒ **两条同源 ⇒ 一次修两个**（这是本批的立项核心）。

### §2.3 为什么它至今没被发现

`save*` 全部把 `writeFileAtomic` 包在 `try/catch` 里：**只 `console.warn` 一句 + 返回 `false`**。而**返回值多数没人查**——摸底档 §4 实测：**token / config 面已接住**（`const persisted = saveTokenRecord(…)` 等），而 **`saveSessionState` 的 8 处调用几乎全部忽略返回值** ⇒ **失败在 session 面上是完全静默的**。

## §3 用户故事

| # | 故事 | 可验层 |
|---|---|---|
| **US-1** | 作为**运维**，目标的杀软/索引器短暂占用不该让一次写入**必然失败**——短暂占用过后它应当自己写成 | T1 |
| **US-2** | 作为**用户**，当写入**最终**失败时，我要能知道（而不是只丢在宿主日志的一句话里，工具返回值上什么都看不见） | T1 |
| **US-3** | 作为**本仓维护者**，我要 `R-13` 从「已知 flake 表」里**移出**（它已被根治），而不是继续用 `G6` 复跑预案掩着 | T2 |
| **US-4** | 作为**用户**，「恢复默认」（`clearUserConfig` 的原子删除）不该是一条**比保存更脆**的路径——它与写入同等暴露在同一 `EPERM` 下 | T1 |
| **US-5** | 作为**下一个会话**，我要知道「重试几次 / 退避多少 / 哪些 errno 可重试」是**有出处的**，不是拍出来的 | T2 |
| **US-6** | 作为**用户**，我要知道这次改的是 `lib/**` ⇒ **必须重启 DSH 才生效**（写进交接页，不擅自重启） | T3（**人工**） |
| **US-7** | 作为**维护者**，我要「重试不会把真失败伪装成成功」这件事被**证明**（锁持续时必败） | T1 |

**层标口径**：**T1** = 进程内 `node --test` 可证 · **T2** = 静态谓词 / 逐字可查 · **T3** = 仅重启后人工核验。

## §4 非功能标准

| # | 标准 | 判据 |
|---|---|---|
| **N-1** | **零新依赖**（纯 node 内建） | `package.json` 依赖键集合不变 |
| **N-2** | **不把三个 store 改成异步**——除非会诊给出**决定性理由**；同步 `Atomics.wait` 已实测可用（摸底档 §3 第 2 条） | 调用面零改动（或改动面在本档显式登记） |
| **N-3** | **重试必须有界**：**次数上限 + 退避上限**，且**同步阻塞的墙钟预算**必须写明（`writeFileAtomic` 在每个 store 的保存路径上，不得拖垮保存） | 常量 + 断言 |
| **N-4** | **只重试可重试的错误类别**（`EPERM` 同族）；**其余错误立即抛**（不把 `ENOSPC` 之类伪装成暂时） | 负控：注入非可重试错误 ⇒ **不重试、立即抛** |
| **N-5** | **重试不得掩盖真失败**：持续占用时**必须最终抛** | 负控（摸底档 §3 第 4 条已实测该性质成立） |
| **N-6** | **失败必须可见**（治果）：最终失败时**调用方拿到的 `false` 要带得动原因**，且**至少一条用户可感的通道**要说出来 | 设计档定落点；**优先 session 面**（静默集中处） |
| **N-7** | **`R-13` 归零**：从台账 §五 已知 flake 表**移出**，并在 §七 记一行「已根治 + 判据 + 变异自证」 | 台账改动同批 |
| **N-8** | **零改面**：`release-check.mjs` · `test/release-check.test.mjs` · `test/fixtures/**` · 基线 10 档（除本批授权面） | 逐档 `git diff --numstat` |
| **N-9** | **每条新判据配负控与阴性对照**，负控**全部在仓外临时副本 / 内存夹具**上做 | 设计档 §8.2 |

## §5 边界与登记面

### §5.1 不做项（**父侧已定四条**；余项待会诊返回后定稿）

| # | 不做 | 理由 |
|---|---|---|
| **1** | **不为「消 flake」而改 `test/session-state.test.mjs` 的断言** | 批 14 的裁定原文：**「加 flake 条目等于把真缺陷记成已知」**——同理，改断言等于把缺陷藏进测试 |
| **2** | **不普适地改所有 store 的失败文案** | 摸底档 §4：静默**集中在 session 面** ⇒ 为一条 flake 牵动 8 处无关调用点是范围蔓延 |
| **3** | **不引入新的持久化格式或配置键** | 本批是「失败路径硬化」，不是契约变更 |
| **4** | **不擅自重启 DSH** | 本批改 `lib/**` ⇒ 写进交接页（US-6） |

### §5.2 登记面（**待会诊返回后定稿**）

**`R-13` 的处置变更**（**从「已知 flake」→「已根治」**）须与台账 §五 / §七 **同批同步**；**`R-51` 结清**（它正是本批的立项来源）。其余新登记待会诊与设计期发现。

### §5.3 不可真机验证清单（**如实登记**）

| # | 项 | 为什么 |
|---|---|---|
| **1** | **真实杀软/索引器的占用是否被重试覆盖** | 生产环境的占用形态**不可在仓内复现**；仓外探针只能构造「另一进程持有句柄」这一个形态（摸底档 §3） |
| **2** | **重启后的真实行为** | 本批改 `lib/**`（US-6） |
| **3** | **宿主日志面的可见性** | 与批 19 同款（`console.warn` 在 DSH 日志里的落点**不可在本仓内生验证**） |
