- 状态：PROPOSED（待用户确认后进入设计）
- 基线：git `f5b7ed7`（v0.7.0 流，125/125 单测绿；版本号锚定 0.1.0→0.7.0 因工程模式写锁顺延至 R1 chore）
- 输入材料：① 用户三轮决策（全插件审计 / 一条龙到修完 / 先入库基线再改）；② 会诊 2/3 回复（deepseek-v4-pro、glm-5.3 实读代码；gpt-5.6-sol 中止）——本文的用户故事与非功能标准大量吸收会诊结论；③ 两个历史会话的实证记录（mal-analyze 会话 040797ed、插件会话 6d06c818）；④ thorough 级审计子代理报告（进行中，结论合并入缺陷登记表）。

## 1. 总体目标（第一层）

把插件从「功能已通、缺陷散布」推进到一条可验证的不变式：

> **四机制（advisor / eng_coder / escalate / consult）的每一次失败都必须可归因、可预测、可恢复；任何预算都必须在平台墙钟内真实有效，或显式迁移到后台执行。**

配套目标：全部已实证缺陷（当前盘点 ≥14 条，审计后定稿）要么修复、要么经用户显式裁决处置；工程过程完成版本锚定与提交纪律。

## 2. 功能用户故事（第二层）

### 评审（advisor）

- **US-1 可预测回落**：作为评审用户，codex 连续失败时我要得到一次、响亮、有归因的自动回落；回落轮自身失败时必须明确终止并给出配置修正指引——不得无限交替（活锁）、不得空响应、不得秒死。
- **US-2 空响应可诊断**：「模型真空输出 / 推理吞掉预算 / 解析丢失 / 基础设施故障」必须可区分可归因；空响应不烧评审轮次、不写入 prior。
- **US-3 token 可恢复**：design 评审批准后，完整 token 在任何通知截断形态下都能被架构师取得（不得因尾部截断丢失导致 eng_coder 无法签收）。〔2026-09-05 审计修订：原「尾部截断丢 token」假设**已驳回**——平台截断为保尾语义（retainTail），token 位于返回文本尾部反而安全；本故事保留为回归测试钉死该平台保证，不再是修复项〕
- **US-4 后台评审单飞**：同一会话同一机制同时最多一个在飞评审任务；重复发起得到明确拒绝而非第二个并行 job。

### 工程模式（eng_coder）与飞刀（escalate）

- **US-5 长任务完整执行**：超过平台墙钟的实现/写任务——**codex 路径与 dsh 子代理路径都算**（按 N-1「回合内 await」判据，2026-09-05 审计修订：原措辞只写 codex，漏 dsh 路径）——不得静默死亡。codex 路径迁移到平台后台任务设施执行，预算真实生效；工具立即返回任务句柄并明确指示「等完成通知再继续后续流程」；交付簿记（touchedFiles 并入、评审预算重置、线程记录）在任务完成回调内恰好一次执行且仅在成功分支。dsh 子代理路径的处置（本轮钳制告警 vs 一并迁移）为设计决策 DP-1，评审时裁定。
- **US-6 写任务安全**：后台写任务与前台编辑不并发写坏状态；截断/半途写入必须响亮告警并给出回滚指引；宿主异常退出后不留孤儿 codex 进程（可检测、可清扫）；followup 线程连续性保持。

### 会诊（consult）

- **US-7 池行能力校验**：会诊池行的 effort 按该行目标模型实际支持档位校验回落，非法档位不再导致子代理秒死；consult 保持跨回合形态不迁移（判据见 N-1）。

### 维护者（所有机制）

- **US-8 保存时拦截**：effort / provider / model 的配置错误在设置页保存时即被目录预检拦截，而不是子代理死亡时才暴露。
- **US-9 进程卫生**：宿主正常销毁与异常死亡两条路径都不留孤儿进程；启动时可清扫陈旧残留。
- **US-10 配置单一事实源**：PUT 校验、配置合并、运行时解析三面白名单保持同步；provider/model/effort 数据源统一为运行时注册表。
- **US-11 工程过程**：版本号锚定；每轮修复独立提交可回滚；文档与代码同步（登记表、README 地图、METHODOLOGY 历史记入）。
- **US-12 失败可读**：任何失败码都能回溯到原始信号（finish.reason、usage、block 计数、exit code、stderr），不需要人工翻源码猜测。

## 3. 非功能标准（第三层）

- **N-1 预算一致性**：以「await 是否发生在回合内工具调用里」为迁移判据——回合内的 codex/子代理等待要么预算 ≤ 墙钟安全余量（budgetCap），要么派后台任务；无一处静默截断。consult 的回复读取发生在后续回合，天然免疫，不迁移。
- **N-2 诊断性**：dsh 流结束与 codex 退出都记录结构化观测（finish.reason.kind、usage input/output/reasoning tokens、block 计数、exit、stderr 尾部），失败分类以此为准，不得依赖单一 exit code（Windows 被杀与崩溃同形）。
- **N-3 并发安全**：per-session-per-mechanism single-flight；后台任务对共享会话状态的合并带代际/版本检查，晚到的完成不得复活已被重置的状态。
- **N-4 进程卫生**：进程树终止、临时目录清理、宿主死亡兜底三条路径各有可验证行为；孤儿可枚举可清扫。
- **N-5 配置单一事实源**：三面白名单同步（见 US-10）；effort 校验分三层——L0 静态枚举（已有）、L1 派发时按目标模型运行时解析（收口到公共派发点，机制层不各自为政）、L2 设置页目录预检。
- **N-6 兼容性**：现有 config.json user 层结构不破坏（只增不改语义）；advisor 收敛协议对外语义（token 门禁、轮次、prior 注入）不变；DSH 平台零修改（maxWallMs 保持默认 600s）。
- **N-7 工程过程**：每轮独立提交 + 版本推进；每个修复 ≥1 回归用例（正常/边界/错误，METHODOLOGY 测试纪律）；交付无测试覆盖 = 评审不通过。

## 4. 范围与非目标

**范围**：四机制 + codex runner 基础设施 + 配置链/设置页 + 工程过程（九个机制主题全覆盖）。

**非目标**：
- 不修改 DSH 平台任何配置与代码（含 maxWallMs）；
- 不迁移 consult 到后台任务形态（N-1 判据下无必要）;
- 不做 mal-analyze / BAC 侧工作（那是另一会话的项目）；
- 不重写机制既有语义——只修缺陷与补观测，行为对外兼容（N-6）。

## 5. 验收标准（项目级）

1. 缺陷登记表（独立文档，审计后定稿）全部条目：修复，或经用户裁决处置（Not-an-issue / Deferred 需登记理由）；
2. 单测全绿（≥125 基线只增不减），每个修复有回归用例映射；
3. 真机验证：advisor（jobs 派发 + 回落链 + token 签发）、eng_coder（一次交付）、escalate（含 followup）、consult（含 codex 行）各跑通一次；复测两个受害场景——「空响应」与「effort 秒死」不再复现或给出可归因诊断；
4. git：基线 + 每轮独立提交、版本号锚定推进、新文档登记入 docs/README.md、METHODOLOGY 文档历史记入本轮。

## 6. 设计决策记录（2026-09-05 用户裁决）

- **D-裁决-1（已裁决：重试）**：dsh 空响应自动重试一次；重试后仍空 → 按可归因失败处理（输出分类诊断，不烧评审轮次、不写 prior）。具体分类形态（模型真空 / 推理吞预算 / 解析丢失）依赖 R1 观测数据，在设计文档定稿。
- **D-裁决-2（已裁决：最近支持档）**：effort 回落到**最近支持档**（用户例：high→high 保持、low→升到 medium），不回落到模型 default。指导原则（用户原话）：**最重要的就是保证真正能用**——所选档位不可用时必须落到一个真实可执行的档位并响亮告警，绝不因档位问题导致任务无法启动/秒死。等距 tie-break（如 medium 缺失、两侧皆有支持档）在设计文档定稿并过评审。
- **D-裁决-3（已裁决：连败 2 次硬停）**：回落轮（dsh 路由）自身连续失败 2 次 → 硬停整个自愈循环，输出配置诊断（双路由状态、失败码、修正指引），不再交替重试。
