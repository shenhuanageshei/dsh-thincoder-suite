# 设计：design token 生命周期（D-30）—— 续期路径 + 精确切除签名腿

- 日期：2026-09-11
- 需求档：[`2026-09-11-token-lifecycle-requirements.md`](./2026-09-11-token-lifecycle-requirements.md)（三层：总目标 / 8 用户故事 / 7 非功能标准）
- 设计输入：**会诊 id 3**（glm-5.3 交付；其余 3 模型超时）——其两条范围缺口（G1/G2）由父侧回代码实证后纳入。
- 术语：**签名腿** = token 第三段 HMAC；**密钥链** = `resolveTokenSecretPath`/`resolveTokenSecret`/`tokenSecret`/fallback 常量；**续期** = 同一 uuid 顺延 `expiresAt`。

---

## §1 方案总则

1. **授权与时限解耦**：评审授予的是「这套设计文档被批准」这一事实；TTL 只是陈旧度护栏。
   故过期时先问「文档集变了吗」——没变则续期，变了则重评。
2. **精确切除，不是整体删除**：签名腿与密钥链删除；**审批码保留但换派生源**（否则 R2 防伪造语义静默归零）。
3. **失败方向**：续期判定 fail-closed（读不到即视为已变）；持久化 fail-safe（写失败仅告警，内存继续）。
4. **门禁 fail-open 不动**（范围边界 §5.1）。

## §3 各单元设计

### FR-T1 两段化 + FR-T2 删除密钥链 + FR-T3 审批码换源

```js
// 铸造（config.engTokenTtlMs 覆盖链不变——D-29 已把该键并入 user 层白名单）
const payload = randomUUID() + ":" + (Date.now() + ttl)
// 校验：恰好两段 + expiresAt 有限 + 未过期（不再有签名段）
// 审批码：sha256(uuid).slice(0,8)   ← 非密钥，无状态、可重算
```

**删除面**（FR-T2）：`advisor.mjs:202-266` 整块 + `crypto` 的 `createHmac`/`randomBytes` 导入
（`randomUUID` 保留——token 与续期都要用）。

**删除后的两处静默必须显式处理**（设计评审 #9）：
① 环境变量 `THINCODER_TOKEN_SECRET` 变为无声 no-op → 启动时若检测到该 env 非空，**打印一次性弃用告警**
（说明密钥链已删除、该变量不再有任何作用），避免运维以为它仍在生效；
② 磁盘上的 `.thincoder/token-secret` 成为孤儿文件 → **显式声明不清理、留档**（删除属破坏性动作，
不在本批范围；README 注明其已被弃用）。

**为什么审批码必须保留**：`[APPROVE:<code>]` 回显由宿主校验（命中才注入完整 token），
其价值是「宿主可算、主代理不可预测」——`uuid` 由宿主 `randomUUID()` 生成且**从不进提示词**，
故 `sha256(uuid)` 对主代理同样不可预测（安全论证详见需求档 §2.3 与 §6 决策 D3）。

**循环依赖**：`advisor-msgs.mjs:12` 反向 import `designApprovalCode`。派生不再用 crypto 后
该函数已属纯字符串函数，**本次保留原位置**（不为可读性做跨模块搬运——那会把「删密钥」批次
扩成结构调整）；代价是继续保留一处有意的环状依赖（既有注释 `advisor.mjs:703-705` 已记录其安全性）。

### FR-T5 续期（本批核心）

**落点 = `eng.mjs` 过期子分支**（`eng.mjs:371-373`）。理由（会诊论证 + 父侧认可）：

| 备选落点 | 否决理由 |
|---|---|
| 写门禁（`eng.mjs:146-170`） | ① 其契约是 fail-open（`:167`），续期判定必须 fail-closed——两者语义互斥；② 门禁唯一输出是 deny 文案，没有回传新令牌串的通道，而续期后**必须**把新串交回调用方；③ 每次 `write`/`edit` 都跑，频率错且无 doc 集上下文 |
| advisor 入口 | 语义倒置：续期正是为了**不**付评审成本；在此续期等于每次过期仍要一次评审调用，或变成无裁决自动放行（比原病更糟） |
| **`eng_coder` 过期子分支** ✅ | 天然 fail-closed（返回 Error，不穿透）；有工具结果通道回传新令牌；是实现的授权判定点；重启回填路径（`eng.mjs:353-364`）正好汇入它——**即头号痛点场景**；变异发生在同步预派发段（`checkInFlightJob` 之前），无并发续期竞态 |

**判定与动作**：

```
过期子分支 →
  读盘记录 loadTokenRecord(sessionId)
  ① 无记录 / 无 docHash      → 「无法续期」文案（指向重评）
  ② docHash 存在 → 重算 hash
       读不到/缺失任一文档    → 视为「已变更」→ 拒绝（fail-closed，不 spawn、不改 state）
       docPaths 缺失/为空     → 「无法续期（记录不完整）」→ 拒绝（收口轮 #4：有指纹却无文档集
                               路径表，重算的是空条目集摘要，必然不等 —— 归此路而非「已变更」；
                               方向不变，仍 fail-closed）
       hash 相同             → 续期：同一 uuid，expiresAt = now + 当前生效 TTL
                               更新 state.designToken + saveTokenRecord + 回传新串
       hash 不同             → 「文档已变更」→ 拒绝并指向重评
  ③ 三段式旧令牌（形状检测）  → 「旧版本令牌」文案（FR-T9）
```

**docHash 定义**（会诊 B7，采纳；`normalize` 规则经设计评审 #1 钉死）：对文档集**路径 + 内容**做摘要——
`sorted(normalize(path) + "\0" + sha256(content))` 再整体 sha256。
仅内容会把「改名/移位」判为未变（评审的指向物已消失而 hash 还绿）；仅路径会漏掉编辑。两者必须都绑。

**`normalize(path)` 规则（钉死，防假阳/假阴）**：`path.resolve(p)` → 反斜杠统一为 `/` →
**不做大小写折叠**（Windows 上 `Docs/A.md` 与 `docs/a.md` 视为不同条目；本仓文档路径大小写稳定，
折叠反而会把两处不同文件误判为同一处。若将来出现大小写不一致引起的续期误拒，按「视为已变更」处理 = fail-closed 方向，可接受）。
规则以 `lib/doc-hash.mjs` 单点实现，续期判定与用例共用同一函数（禁两处各写一份）。

**快照时点 = 待批令牌铸造时**（会诊 B6，采纳）：`advisor.mjs:1386-1388` 铸造 `pendingDesignToken` 时
把当轮的 `documents` 一起快照进 session state。
**快照**用 = **历轮文档集之并集**（设计评审 #2 采纳）：评审的授权语义覆盖「讨论中出现的全部文档」，
故后续轮次并入 `[B,C]` 时，B/C 也应被绑进指纹——否则「首铸轮 `[A]`、后续轮并入 `[B,C]`」的镜像场景下，
B/C 漂移而续期仍放行，削弱 US-3。**绝不使用 `eng_coder` 的 `args.docs`**（那是任务书的阅读清单，
由主代理控制，不是评审范围）。

**空文档集**（会诊 B8，采纳）：评审未传 `documents` → **不写 docHash** → 续期一律拒绝
（与「无 docHash」同一条安全缺省）。理由：空集的 hash 恒等，会让续期护栏真空为真。

**续期返回契约**（会诊 B9）：返回值**必须含新令牌串** + 「替换你手里的副本」指引；
旧串在下一次调用即 mismatch。同会话两个 `eng_coder` 并发用同一过期令牌时，
第二个会撞 `token !== state.designToken`——文案需指明「已被本次会话的续期取代，用上一次 eng_coder 返回的新令牌」。

### FR-T6 四条过期路径文案

| 情形 | 文案要点 |
|---|---|
| 已续期 | 成功 + 新令牌串 + 「替换副本」+ 当前有效期（>24h 时显示**日期**而非 `HH:MM`） |
| 文档已变更 | 明说**哪个**文档集变了 → 重跑 design review |
| 无法续期（无 docHash / 旧记录 / 记录不完整：有 docHash 但 `docPaths` 缺失/为空，见 §3 FR-T5 ② 与 §4.1 收口轮 #4） | 明说原因（评审未绑定文档集；或记录缺文档集路径表、无法判断文档是否变更）→ 重跑 design review |
| 三段式旧令牌 | 明说「旧版本令牌，形状已不兼容」→ 重跑一次即可 |
| 写门禁 deny（`eng.mjs:164`） | 令牌**已过期**时不得再说「先写设计文档」（误导）→ 指向续期/重评 |

`advisor.mjs:1444` 的「有效至 HH:MM」在 7d 下无意义 → TTL > 24h 时改显示日期。

### FR-T7 `main.md:19` 口径修正

现行文说会诊「绑定当前回合，用户打断或回合结束即终止」。与实现矛盾：
`consult.mjs:8-14`（D-28）记录子代理**不继承** `exec.signal`，终止只走 `consult_stop` /
`consultTimeoutMs` 看门狗 / session 销毁三条显式路径。
新口径须同时写清两件事：**跨回合存活**（打断/回合结束不杀），且**有界**（受 `consultTimeoutMs` 约束，缺省 10min、可配）。

### FR-T8 token-store 两个缺口（会诊 G1/G2，父侧实证）

1. **保存路径丢字段**（`token-store.mjs:72-80` 显式重建三字段）→ 追加 `docHash`、`docPaths`
   （缺省不写；旧记录无此字段属正常，见 N7）。
2. **清扫删续期输入**（`:84-89` 过期即删）→ 新规则：
   - 畸形记录（非对象 / `expiresAt` 非有限数）→ **仍删**（保留原防累积意图）；
   - 已过期 **且有 `docHash`** → **保留**（它是续期输入），但加保留期上限（建议 30d，防无界累积）；
     判定公式写死：**`now > expiresAt + ENG_TOKEN_TTL_MAX_MS` → 删除**（锚点 = `expiresAt` 起算，
     不是 `issuedAt`；常量复用 D-29 既有值，不新增旋钮）。设计评审 #8 已钉死此锚点。
   - 已过期 **且无 `docHash`** → 删除（现状语义）；
   - 未过期 → 保留。
   `ENG_TOKEN_TTL_MAX_MS` 已是 30d（D-29），保留期取同值可复用常量、无需新旋钮。

### FR-T9 旧格式迁移

`validateDesignToken` 增加形状检测（`split(":").length === 3`）→ 返回可区分的失败原因，
`eng.mjs` 据此给「旧版本插件签发的令牌」文案。**干净切换、不做旧格式兼容验签**
（先例：v2 废除 `[DESIGN-TOKEN:...]` 回显时同款——保留旧通道等于保留钓鱼面）。
现场影响有限：TPU 由 D-29 可配，本机 base 仍是 1h。
