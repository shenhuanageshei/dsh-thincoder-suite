## §1 总目标（一句话）

**把会诊从「发起后靠调用方记得回来轮询」改成「结束时自动投递、回来后必须处置、处置结果默认落档」**——其中前两条**照搬上游 R17 已裁定的形态**（本仓只是晚了六天没跟），第三条**是本仓要走在上游前面的新设计**。

## §2 背景与问题

| # | 问题 | 根因 | 实测 |
|---|---|---|---|
| **P1** | **会诊结束时无人知晓、无物推动** | 本仓停在 pre-R17 协议：`consult_start` 非阻塞返回，**消费全靠调用方主动调 `consult_check`** | 本会话我自己撞了**三到四次**：发完会诊就结束回合等通知，而**没有通知会来**；用户两次追问「会诊结束了没有」 |
| **P2** | **「回来」这个动作没有任何机制保证** | 协议假设调用方会回来，**而唯一的保证是一句提示词** | `lib/index.mjs:1034`「DO NOT end your turn … expecting to be woken」——**靠自觉** |
| **P3** | **回复到达后常常只被「总结/梳理/对比」，不被落实** | 没有把「逐条判断采纳与否并处置」写进任何契约；本仓的 `*-consult-minutes.md` 只是**惯例**（`METHODOLOGY.md:41` 把它归为「批次文档 = 主代理」），**不是机制** | 本会话我确实落了纪要，但**那是因为用户反复要求**；**代码侧没有任何东西要求它** |
| **P4** | **上游的分叉从未被记录** | 移植时上游尚未改造；六天后上游改造了，**本仓不知** | §0.1 |

**靶心 = P2**（「回来」无机制保证）；**P3 是本批唯一「上游也没有」的新设计**。

## §3 用户故事

| # | 用户故事 | 判定句（可机验 / 可人验） |
|---|---|---|
| **US-1** | 作为**主代理**，我希望会诊**结束时自动收到通知**，而不用记得回来轮询 | 全 settle 时**产生一次投递**（忙时注入下一步 / 空闲开回合），且**不需要调用方任何动作** |
| **US-2** | 作为**用户**，我希望主代理拿到会诊结果后**停下来向我汇报**，而不是径直继续改代码 | 投递到达后被消费的那个回合**产出一份面向我的汇报**（含「我采纳什么 / 不采纳什么 / 为什么」），**然后停下** |
| **US-3** | 作为**用户**，我希望在我**已明确目标 / 无人值守 / 已明确授权**时，主代理**不必每次停下** | 存在**显式开关**（配置或工具参数），开启时投递**不再强制停止**；**关闭（缺省）时 US-2 成立** |
| **US-4** | 作为**审计员**，我希望会诊的**每一条意见都被分类处置**（采纳 / 不采纳 / 待定），而**不是只被总结** | 落档物里**每条意见恰有一条处置**，且**不采纳的必须给理由** |
| **US-5** | 作为**下一批的维护者**，我希望纪要**默认落盘**（而不是只活在对话里） | 缺省行为 = **写出纪要档**；豁免须**显式**且**留痕**（写明为何豁免） |
| **US-6** | 作为**维护者**，我希望本仓的 consult 协议**与上游的现状对齐或有据地偏离** | 代码 / 文档中**不再有「consult 无通知」这类无据陈述**；偏离处须**注明上游坐标**（提交 / 版本） |
| **US-7** | 作为**调用方**，我希望 `consult_check` 的去留**明确**（要么在、要么明确退役），不留半套协议 | 二选一并**描述面与注册点同步清零**（上游 R17 的做法：`setup.mjs:269-270`「setup 注册点与描述面同步清零」） |
| **US-8** | 作为**审计员**，我希望悬空引用**不再指向不存在的档** | §0.3 的 **X-1** 被处置（改指真实落点或删引用）——**归批 14** |

## §4 非功能标准

| # | 标准 | 判定 |
|---|---|---|
| **N-1** | **不得依赖插件自造投递设施**，若平台已有等价能力 | DSH 的 `dsh-tool-jobs` 已提供「**injected into a busy owner's next step, or opening a turn on an idle one** under the default `wakeup` delivery」（`lib/index.js:10-12`）⇒ **优先复用它**，而非照搬上游的 `_pendingAsyncResults` 自造容器 |
| **N-2** | **交付必须能在平台墙钟内完成** | 本仓 dsh 子代理**同步调用活不过 600s**（`eng.mjs:914-916`）⇒ 实施必须传 `background: true` 或拆 stages |
| **N-3** | **零新增依赖** | 本仓一贯约束 |
| **N-4** | **不新增测试档 / 不新增顶层 `test(`** | 台账 §三零改（批 13 先例） |
| **N-5** | **`lib/**` 需重启才生效**——本批交付须在交接页登记这一项 | 与前两批同类 |
| **N-6** | **不擅自重启 DSH、不擅自改用户配置** | 常设约束 |

## §5 边界与登记面

### §5.1 本批不做

| # | 不做项 | 理由 |
|---|---|---|
| 1 | **不照搬上游的 `_pendingAsyncResults` 自造容器** | 平台已有等价设施（N-1）⇒ 自造是**重复实现**且要复刻上游的挂起 / 唤醒 / 容量全套 |
| 2 | **不改 consult 的只读子代理语义** | 上游明文「会诊子 agent 只读」；本仓同 |
| 3 | **不做「模型间交叉通信」** | 上游明文列为不做 |
| 4 | **不做「部分 settle 提前注入」** | 上游明文「**全 settle 才入 digest 流**」（意见全貌才可判断）；本批沿用 |
| 5 | **不修 X-1（悬空引用设计档）** | 归批 14（同物种） |
| 6 | **不改 consultTimeoutMs / consultTurns 的语义** | 本批只动**投递与消化**，不动预算 |
| 7 | **不给「纪要」定内容模板之外的机器强校验** | 见 §5.2 R-41 的裁定理由 |
