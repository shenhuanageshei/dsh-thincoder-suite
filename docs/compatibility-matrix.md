# 平台兼容性矩阵（装错版本会报什么，装哪个版本）

<!-- doc-shape

> **为什么有这个档**：本插件是 DSH 的 bundle 插件，`package.json#peerDependencies` 声明了它要的 DSH 平台版本。
> **平台会按这条声明做安装闸门**（不满足 ⇒ 拒绝装载），所以「装错版本」的表现是**装不上或起不来**，不是功能异常。

---

## §一 兼容性矩阵（以 `git tag` 为准，逐条核对过 `package.json#version` 与 `peerDependencies`）

| 版本（tag） | 声明要求的 DSH | 说明 |
|---|---|---|
| **v0.30.1** | `^0.2.0-rc.1` | 第一个显式声明 peer 的版本 |
| **v0.31.0 · v0.31.1 · v0.32.0** | `^0.2.0-rc.1` | 仍兼容 0.2.0-rc.1 线 |
| **v0.33.0** | `^0.2.1-rc.2` | ★ **断点**：平台要求自此版抬升到 **0.2.1-rc.2** |
| **v0.34.0 · v0.35.0 · v0.36.0 · v0.37.0 · v0.38.0** | `^0.2.1-rc.2` | 当前线 |

**v0.29.11 及更早**：`package.json` **没有** `@deepseek-ai/dsh` 的 peer 声明（实测为空）——
本档**不对未声明的版本作断言**（那时支持面靠当时的文档记述，不在本档口径内）。

★ **一句话结论**：**DSH `0.2.0-rc.1` 线装 ≤v0.32.0；DSH `0.2.1-rc.2` 及更新的装 ≥v0.33.0。**

---

## §二 怎么自己核一个版本要什么平台（三种等价查法）

```bash
# ① 看 tag 说明（本仓每个 tag 的说明里都带「平台要求：DSH …」）
git tag -n1 -l v0.33.0

# ② 直接读那个版本声明的 peer
git show v0.33.0:package.json     # 看 peerDependencies["@deepseek-ai/dsh"]

# ③ 读该版本记录的契约基线（平台触点锁）
git show v0.33.0:lib/contract-baseline.mjs
```

## §三 依据与边界

- **数据来源**：对每个 tag 的提交执行 `git show <tag>:package.json` 读取 `peerDependencies["@deepseek-ai/dsh"]`（2026-10-20 实测）。
- **已验证**：v0.30.1 / v0.31.0 / v0.31.1 / v0.32.0 / v0.33.0 / v0.34.0 / v0.35.0 / v0.36.0 / v0.37.0 / v0.38.0 的版本与 peer 逐条核过；v0.29.11 及更早的「无 peer 声明」也已实测。
- **未覆盖**：本档**不**逐版本核实「实际运行时行为」——只陈述**声明**；声明与实现是否一致由各版本的测试与契约锁承担。
- **维护纪律**：**每次发版打 tag 时，tag 说明必须带「平台要求：DSH <peer>」**（本次补打的 v0.31.0–v0.37.0 已按此格式）；peer 范围一旦变更，本档同批更新并注明断点版本。
