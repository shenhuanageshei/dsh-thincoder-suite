# 平台兼容性矩阵（装错版本会报什么，装哪个版本）

<!-- doc-shape
count-marks: 条|处|个|版
-->

> **为什么有这个档**：本插件是 DSH 的 bundle 插件，`package.json#peerDependencies` 声明了它要的 DSH 平台版本。
> **平台会按这条声明做安装闸门**（不满足 ⇒ 拒绝装载），所以「装错版本」的表现是**装不上或起不来**，不是功能异常。

## §二 怎么自己核一个版本要什么平台（三种等价查法）

```bash
# ① 看 tag 说明（本仓每个 tag 的说明里都带「平台要求：DSH …」）
git tag -n1 -l v0.33.0

# ② 直接读那个版本声明的 peer
git show v0.33.0:package.json     # 看 peerDependencies["@deepseek-ai/dsh"]

# ③ 读该版本记录的契约基线（平台触点锁）
git show v0.33.0:lib/contract-baseline.mjs
```

## §三 依据与边界

- **数据来源**：对每个 tag 的提交执行 `git show <tag>:package.json` 读取 `peerDependencies["@deepseek-ai/dsh"]`（2026-10-20 全量实测；批 45 于 2026-11-06 复核 `v0.39.0` 已打 tag 且 peer 仍为 `^0.2.1-rc.2`）。
- **已验证**：v0.30.1 / v0.31.0 / v0.31.1 / v0.32.0 / v0.33.0 / v0.34.0 / v0.35.0 / v0.36.0 / v0.37.0 / v0.38.0 的版本与 peer 逐条核过；v0.40.0 **已核**（2026-11-07 打 tag 后按同一条命令复核：`git show v0.40.0:package.json` ⇒ `"version":"0.40.0"`、`peerDependencies["@deepseek-ai/dsh"] = "^0.2.1-rc.2"`，与本行一致）；v0.29.11 及更早的「无 peer 声明」也已实测。`v0.39.0` 是**既有版本**（批 45 补登），其 peer 见 §一 那一行（由 `git show v0.39.0:package.json` 读出）。
- **平台侧验证（新增口径）**：「已在平台 `X` 上完成验证」只出现在 §一 的**说明列**（平台版本属于平台侧事实，塞进 tag 清单会把两种口径混为一谈）。
- **未覆盖**：本档**不**逐版本核实「实际运行时行为」——只陈述**声明**；声明与实现是否一致由各版本的测试与契约锁承担。
- **维护纪律**：**每次发版打 tag 时，tag 说明必须带「平台要求：DSH <peer>」**（本次补打的 v0.31.0–v0.37.0 已按此格式）；peer 范围一旦变更，本档同批更新并注明断点版本。
